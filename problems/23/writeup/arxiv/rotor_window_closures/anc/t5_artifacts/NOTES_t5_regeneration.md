# t=5 certificate artifacts — regeneration record (2026-07-17)

This directory contains regenerated `t=5` certificate artifacts for the
paper's Table `tab:t5artifacts`. The historical artifacts were session
records of the programme ledger and had been deleted from the repository
(adversarial review pass 2026-07-17, issue I1). Everything below was
regenerated on 2026-07-17 from the archived scripts in `anc/`, on the same
machine as the original 2026-07-12 runs.

Environment: Python 3.12.4, OR-Tools CP-SAT 9.14.6206, NetworkX 3.6.1,
PySAT 1.8.dev24 with CaDiCaL 1.9.5 (`cadical195`). All arithmetic integer
or Boolean; every run exited 0; no verdict was accepted from a timed-out
solve (all INFEASIBLE statuses are completed proofs).

The paper's cited prefixes are prefixes of the `canonicalSha256` field
embedded in each JSON artifact (SHA-256 of the compact key-sorted JSON
payload, excluding the hash field itself) — not hashes of the file bytes.

## Headline results

1. **The twelve split-infeasibility certificates regenerate bit-exactly.**
   Rerunning `rooted_t5_support_cp_sat.py` with the historical invocation
   (recovered from the archived launch scripts; see below) reproduces the
   *identical* canonical payload hash for all twelve claimed-infeasible
   splits — every prefix in rows 1–3 of `tab:t5artifacts` matches, and the
   verdict is INFEASIBLE with `supportsSolved=0` in each case. This also
   *fixes the order-17 per-split mapping* left open in the session record:
   `4d450ca0` = split (7,10), `f76b9d64` = (8,9), `325012ec` = (12,5) —
   exactly the order printed in Proposition `prop:order17`.

2. **The three claimed-feasible order-17 splits are support-feasible.**
   Fresh runs at `--max-supports 1` give `supportsSolved=1` for (9,8),
   (10,7), (11,6). (The historical 3,000-support staged *no-hit* artifacts
   `95dbc901`/`d612c59e`/`31d82c62` are bounded, non-probative sweeps and
   were not repeated; their prefixes remain session records.)

3. **The sweep trajectory is solver-nondeterministic; the circuit-level
   artifacts therefore do not replay byte-exactly.** A rerun of the
   historical `9+9` classifier-v sweep (`--max-supports 1000`, workers 8)
   produced a hit at support #343 on a *different* support graph
   (`Q??????wE_BSJOs?Y?D??G?@???`) than the historical hit at support #298:
   with `num_search_workers=8` the CP-SAT portfolio races, so the
   enumeration order (support solution + nogood sequence) is not
   reproducible run-to-run. The fresh sweep is kept here, clearly renamed
   (`t5_sweep_l9_r9_classifier_v_fresh20260717*`), as an honest record: its
   hit also passes the independent verifier and its owner is also dead
   (scope UNSAT) — consistent with the section's open question. It is NOT
   the paper's #298 artifact.

4. **Both printed circuits were regenerated by pinning the graph.**
   `rebuild_t5_local_classifier_hit.py` (in `anc/`) fixes the printed
   graph6 string and reruns the archived engine's own circuit stage
   (`choose_minimal_circuit`, imported from `rooted_t5_support_cp_sat.py`)
   at the recorded (owner, active) pairs: #298 at (0,17), #264 at (0,9).
   Both hits exist; atom supplies are 32 (#298) and 30 (#264), matching the
   paper; the independent exact verifier passes on both. Two independent
   runs of the #298 rebuild (this session and the companion #298-extension
   session) produced canonically identical payloads (`ff1c1209…`).

5. **Every downstream verdict reproduces on the pinned payloads,** and the
   scope-certificate CNF sizes match the recorded figures exactly:
   - #298 all-row dead owner: CP-SAT gate INFEASIBLE
     (`check_t5_active_scope_profile.py`) and CaDiCaL UNSAT at
     **1680 variables / 5239 clauses** — precisely the counts printed in
     the paper;
   - #264 all-row dead owner: CP-SAT gate INFEASIBLE and CaDiCaL UNSAT at
     **1645 variables / 5140 clauses** — precisely the counts in the
     archive REPORT;
   - #264 tail blanket: PASS, with per-edge UNSAT tests exactly on the two
     edges {1,9} and {2,9} of facts (f1)/(f2);
   - #264 ambient max-cut extension: all **eight** shore splits INFEASIBLE
     (primary, lazy exact separation) and the independent CaDiCaL replay
     returns `PASS_ALL_EIGHT_SPLITS_UNSAT`.

   The canonical hashes of these regenerated circuit-level artifacts differ
   from the historical prefixes (`c1d474d7`, `48ce1638`, `f5c0cbca`,
   `a8a160d5`, `6595501f`, `d9e73413`, `79471ef0`, `c7fbcc70`, `3720a8c2`),
   because the rebuilt payload schema differs from the sweep payload and
   every downstream artifact embeds the source payload's hash. Verdicts,
   graphs, (owner, active) pairs, supplies, CNF sizes, forced tail edges
   and split statuses all agree with the paper's claims.
