# L05 audit: OEIS A389182 and GitHub issue 143

## Decisive assessment

**Novelty gate: PASS for the asymptotic upper-bound target, relative to the
assigned sources.**  OEIS A389182 and issue 143 establish prior art for the
exact finite values through (N=69), one extremizing witness for each of those
values, and the reflected-Sidon pattern (S\cup(k-S)).  They do **not** prove

\[
F(N)\leq \left(\frac{2}{\sqrt3}+o(1)\right)\sqrt N,
\]

give any asymptotic upper bound with leading constant (2/\sqrt3), or give an
infinite admissible family exceeding that constant.  A result consisting only
of the values through 69, the supplied exhaustive search, or the reflected
Sidon construction/pattern is **not novel**.  A proof of the target upper bound
is not anticipated by these two records.

## Exact formulation and source scope

The [OEIS record, revision #17 of 2025-10-28](https://oeis.org/search?q=id%3AA389182&fmt=text)
defines (a(n)) as the maximum cardinality of a subset of
\(\{1,\ldots,n\}\) for which all sums (a+b), with (a\leq b), are distinct
except possibly one.  This is exactly (F(n)) in `STATEMENT.md`:

- representations are unordered because (a\leq b);
- diagonals count: the examples use (2+2) and (4+4);
- at most one sum-value may have multiplicity at least two;
- that exceptional value has no multiplicity cap.  The OEIS comment says this
  explicitly, and its (n=7) example permits
  (8=1+7=2+6=4+4), including a diagonal.

The primary 1992 statement is also the same asymptotic problem.  For
\(a_1<\cdots<a_k\leq n\), Erdos assumes there is only one (m) for which
\(a_i+a_j=m\) has more than one solution, records that
\(\max k\geq (2/\sqrt3)n^{1/2}\) is possible, and conjectures
\(\max k=(1+o(1))(2/\sqrt3)n^{1/2}\); see
[Erdos (1992), pp. 39-40](https://hrj.episciences.org/125/pdf#page=6).
That scan does not print an (i\leq j) qualifier at this point.  The current
[official Problem 864](https://www.erdosproblems.com/864) and OEIS entry do,
and the OEIS examples and all linked programs confirm the diagonal-inclusive
unordered convention.  Since the condition restricts only how many values of
(m) are repeated, it places no bound on the multiplicity of the one exception.

The headline theorem in the publisher abstract of the cited 1991 paper is a
different result: for a genuine Sidon sequence
\(1\leq a_1<\cdots<a_k\leq n\), if (S(n)) is the maximum number of pair sums
below (n), it states
\(1-1/\sqrt2-\varepsilon\leq S(n)/n\leq1/\pi+\varepsilon\).
That theorem is not an upper bound for (F(N)); Problem 864 is one of the
paper's related problems.  See the
[primary publisher record and abstract](https://www.sciencedirect.com/science/article/pii/0022314X9190083N)
and [DOI](https://doi.org/10.1016/0022-314X(91)90083-N).

## Code audit

### OEIS inline program

The program in [A389182](https://oeis.org/A389182) is an exhaustive increasing
recursion.  For a candidate set it loops over `new_nums[ind:]`, so every
unordered pair occurs once and every diagonal occurs once.  It accepts exactly
when the number of sum-values whose count exceeds one is at most one; it never
caps the count at that value.  It is therefore a direct implementation of the
target definition.  Its printed range is only `range(1, 20)`, so by itself it
computes (N=1,\ldots,19), not the terms through 69.  Its mutable default list
is not mutated in place and does not alter the result.

### Simple issue script

The [commit-pinned simple script](https://github.com/davidspencer6174/erdos_problem_scripts/blob/ee7cabf994741b97f2cc9adad8d2aefc7156cb65/erdos_864_simple.py#L3-L45)
also enumerates every subset in increasing order.  It adds each old-new sum
once and adds `candidate_next*2` once.  `exception_count` increases only when a
sum count crosses from one to two; a third or later representation of the
existing exception is allowed.  The source loop requests (N=1,\ldots,49),
but issue 143 says it was run only through (N=40).  No separate simple-script
output log is linked, so agreement through 40 and equality of its witnesses
with the optimized script remain author-reported facts.

### Optimized script and maximality

The [commit-pinned optimized script](https://github.com/davidspencer6174/erdos_problem_scripts/blob/895c1373e03ead129e9619f9b33f47eca924efbf/erdos_864.py#L3-L66)
has the following exact behavior.

1. Bits of `bitfield` are selected elements.  Adding (c) creates one bit for
   every (a+c) with previously selected (a<c), plus the diagonal bit (2c)
   ([lines 30-32](https://github.com/davidspencer6174/erdos_problem_scripts/blob/895c1373e03ead129e9619f9b33f47eca924efbf/erdos_864.py#L30-L32)).
2. It rejects an extension if it creates two new repeated sum-values, or one
   new repeated value after an exception already exists
   ([lines 34-45](https://github.com/davidspencer6174/erdos_problem_scripts/blob/895c1373e03ead129e9619f9b33f47eca924efbf/erdos_864.py#L34-L45)).
   Collisions at the masked existing exception are exempt, so its multiplicity
   is arbitrary.
3. Strictly increasing candidate recursion visits every subset exactly once.
   The only pruning compares current size plus the number of remaining
   candidates with the best size already found
   ([lines 20-28](https://github.com/davidspencer6174/erdos_problem_scripts/blob/895c1373e03ead129e9619f9b33f47eca924efbf/erdos_864.py#L20-L28)); it cannot remove a branch that would improve the maximum.

One implementation comment is literally inaccurate after an exception obtains
three representations: `sums_once` can then also contain the exception bit, so
it is not always the set of sums represented *exactly* once.  This does not
change acceptance, because `new_exceptions = collisions_with_once &
~exception_sums` always removes that masked bit before the rejection test.
No correctness defect was found in the search or pruning logic.

Audit checks performed on the pinned artifacts:

- all 69 logged witnesses have the stated cardinality and at most one repeated
  unordered, diagonal-inclusive sum-value;
- all 69 logged cardinalities equal the OEIS b-file;
- an independent count-recomputing recursion agrees with the optimized state
  machine for every (1\leq N\leq20).

The linked output is a run log, not a checkable optimality certificate: it has
no Python version, machine description, test log, formal certificate, or
independent complete rerun through 69.  Source-level exhaustiveness supports
the maximality claim, but OEIS approval itself was sequence review, not a
peer-reviewed proof of the computation.

## Structural claim (S\cup(k-S))

The OEIS comment says that "many" observed extremizers have this form.  The
[issue body](https://github.com/teorth/erdosproblems/issues/143) is deliberately
weaker than a classification: its author retained one optimum per (N), did
not enumerate all optima, and expressly declined to claim that the form is
mandatory.

A mechanical audit gives the exact finite content of the observation:

- 66 of the 69 linked witnesses are reflection-symmetric and can be written
  (A=S\cup(k-S)) with the canonical lower-half (S) a genuine Sidon set;
- the three linked witnesses not of this form are those for (N=6,10,14);
- every cardinality-jump witness is of this form;
- at every jump, the logged set uses exceptional sum (k=N+1), not (k=N).

Thus, with (N) denoting the ambient endpoint as it does in Problem 864, the
issue's literal notation (S\cup(N-S)) is off by one for its own jump
witnesses (or else reuses (N) there to mean the exceptional sum).  The exact
jump data are below; in every row (A=S\cup(k-S)), and the displayed (S) is
Sidon under the same unordered, diagonal-inclusive convention.

| ambient (N) | (F(N)) | (k) | canonical (S\) | (r_A(k)) |
|---:|---:|---:|:---|---:|
| 1 | 1 | 2 | \(\{1\}\) | 1 |
| 2 | 2 | 3 | \(\{1\}\) | 1 |
| 3 | 3 | 4 | \(\{1,2\}\) | 2 |
| 5 | 4 | 6 | \(\{1,2\}\) | 2 |
| 7 | 5 | 8 | \(\{1,2,4\}\) | 3 |
| 11 | 6 | 12 | \(\{1,2,4\}\) | 3 |
| 15 | 7 | 16 | \(\{1,2,4,8\}\) | 4 |
| 20 | 8 | 21 | \(\{1,2,4,8\}\) | 4 |
| 25 | 9 | 26 | \(\{1,2,4,8,13\}\) | 5 |
| 31 | 10 | 32 | \(\{1,2,4,9,13\}\) | 5 |

The table demonstrates multiplicities as high as seven, but only for these
finite witnesses.  It supplies no asymptotic structural theorem.

A genuine Sidon set (S) alone is not sufficient to make
(S\cup(k-S)) admissible: cross-type sums can create further collisions.  For
example, (S=\{1,3\}) is Sidon, but with (k=5) the union is
\(\{1,2,3,4\}), which has repeated sums 4, 5, and 6.  The known asymptotic
lower construction cited on the [official problem page](https://www.erdosproblems.com/864)
adds a separation hypothesis: take a Sidon set
\(B\subset[1,N/3]\) of size \(\sim\sqrt{N/3}\) and use
\(B\cup\{N-b:b\in B\}\).  This yields size
\((1+o(1))(2/\sqrt3)\sqrt N\), with (N) as the sole possible repeated sum
and with no cap on its multiplicity.  Issue 143's construction remark is
therefore known lower-bound prior art, not evidence for the target upper bound
or for necessity of reflection symmetry.

## Issue 143 evidentiary status

[Issue 143](https://github.com/teorth/erdosproblems/issues/143) was opened on
2025-10-22 and closed on 2025-11-03 because the sequence was approved.  Its
three comments add no theorem:

- a [quick ChatGPT check](https://github.com/teorth/erdosproblems/issues/143#issuecomment-3434866052)
  reportedly matched only through (N=15);
- the [second comment](https://github.com/teorth/erdosproblems/issues/143#issuecomment-3439908144)
  records submission of the OEIS draft;
- the [closing comment](https://github.com/teorth/erdosproblems/issues/143#issuecomment-3481631859)
  records OEIS approval.

Accordingly, neither closure of the issue nor OEIS approval is a claim that
Problem 864 has been solved.  The exact finite computation and observed
reflection pattern are prior art; the asymptotic upper bound remains open in
these sources.
